This guide walks you through running Electric Elephant and connecting it to an AI tool. You need a reachable **PostgreSQL** instance (local Docker, managed service, or tunneled host).

## Prerequisites

Before starting, ensure you have:
- Node.js 20+ installed (for NPM method) **or** Docker installed
- Access to an AI tool (Claude Desktop, Claude Code, Cursor, or VS Code)
- A PostgreSQL server and a connection string (or `dbhub.toml` / `DB_*` variables)

## Choose Your Transport

Electric Elephant supports two [transport protocols](/config/command-line#transport):

| Transport | How It Works | Best For |
|-----------|--------------|----------|
| **stdio** | AI tool spawns Electric Elephant as a subprocess | Local desktop apps, single-user setups |
| **http** | Electric Elephant runs as a standalone HTTP server | Web clients, shared servers, remote access |

## Step 1: Start Electric Elephant (HTTP)

<Note>
If using **stdio** transport, skip this step — your AI tool will spawn Electric Elephant as a subprocess and pass `--dsn` or equivalent configuration.
</Note>

For **http** transport, start the server with a Postgres DSN (adjust user, password, host, and database):

<Tabs>
  <Tab title="NPM">
    ```bash
    npx electric-elephant --transport http --port 8080 --dsn "postgres://postgres:postgres@localhost:5432/postgres"
    ```
  </Tab>

  <Tab title="Docker">
    ```bash
    docker run --rm -p 8080:8080 electric-elephant --transport http --port 8080 --dsn "postgres://postgres:postgres@host.docker.internal:5432/postgres"
    ```

    On Linux hosts where `host.docker.internal` is unavailable, use `--network host` or point the DSN at a container-accessible address.
  </Tab>
</Tabs>

The server listens at `http://localhost:8080`. The workbench is at `/`, and the MCP endpoint is at `/mcp`.

## Step 3: Try It Out

Try these example prompts in your AI tool (adapt table names to your schema):

<AccordionGroup>
  <Accordion icon="database" title="List available schemas">
    ```
    What schemas are available in the database?
    ```

    The AI will use the `db://schemas` resource to list schemas.
  </Accordion>

  <Accordion icon="table" title="Show tables in a schema">
    ```
    What tables are in the public schema?
    ```

    The AI will use the `db://schemas/public/tables` resource.
  </Accordion>

  <Accordion icon="magnifying-glass" title="Run a read query">
    ```
    Show the first 10 rows from my_table with explicit columns
    ```

    <Note>
    With the default [PII/clinical guard](/tools/execute-sql#pii-and-clinical-data-guard), `SELECT *` may be rejected; prefer explicit columns after inspecting the table with `search_objects`.
    </Note>
  </Accordion>

  <Accordion icon="pen" title="Change data">
    ```
    Update a row in my_table (give a safe predicate)
    ```

    <Note>
    Mutating SQL requires `execute_sql` not configured with `readonly = true`, and may require `--allow-destructive-sql`. See [Read-Only Mode](/tools/execute-sql#read-only-mode).
    </Note>
  </Accordion>
</AccordionGroup>

## Step 4: Install the Agent Skill (Optional)

Electric Elephant provides an [agent skill](https://github.com/ajgreyling/electric-elephant/tree/main/skills/badger-db-mcp) that teaches your AI tool the best-practice workflow for database querying — explore the schema first, then write precise SQL.

```bash
npx skills add ajgreyling/electric-elephant
```
